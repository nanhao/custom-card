# 设计 #38 — 测试用例集

## 1. 初始抽牌堆 (`get_initial_draw_pile`)

### TC1.1 — 牌堆组成
- **前置**：无
- **操作**：调用 `get_initial_draw_pile()`
- **预期**：返回包含 7 张牌的列表，具体为：3 张 ATTACK、2 张 DEFENSE、1 张 ENERGY、1 张 BUILD
- **预期**：列表中不包含 HEAVY 和 COUNTER

### TC1.2 — 返回全新副本
- **前置**：无
- **操作**：连续两次调用 `get_initial_draw_pile()`，修改第一次返回的列表
- **预期**：第二次调用结果不受第一次修改影响（两份独立副本）

## 4. 前端状态剩余回合展示

### TC4.1 — 状态标签包含剩余回合数
- **前置**：创建游戏并完成至少 1 回合，使某玩家获得防御状态
- **操作**：渲染 GameBoard，检查状态标签文本
- **预期**：标签显示格式为 `defense (N)` 或 `guard (N)`，其中 N 为剩余回合数（> 0）

### TC4.2 — 无状态时不显示标签区
- **前置**：创建游戏，双方状态列表为空
- **操作**：渲染 GameBoard，检查 `.status-tags` 区域
- **预期**：不渲染 `.status-tags` 元素

### TC4.3 — 脆弱状态也显示回合数
- **前置**：游戏中某方获得脆弱状态
- **操作**：渲染 GameBoard，检查状态标签
- **预期**：脆弱标签也显示剩余回合数

## 5. 游戏完整流程回归

### TC5.1 — 基础回合流程
- **前置**：创建 PVP 游戏
- **操作**：执行至少 3 个完整 cycle（9 回合）的游戏流程
- **预期**：每回合正常结算，HP 正确变化，游戏不崩溃

### TC5.2 — BUILD 构建
- **前置**：创建游戏（初始能量=2）
- **操作**：打出 BUILD 卡并选择构建 ATTACK（build_cost=1）
- **预期**：构建成功，能量减少 1（2→1），抽牌堆新增 1 张 ATTACK

### TC5.3 — Cycle 结束 HP 流血
- **前置**：游戏进行到 Cycle 第 3 回合（round_in_cycle=3）
- **操作**：完成该回合
- **预期**：双方各失去 1 HP，新 Cycle 开始

### TC5.4 — 状态计时正常递减
- **前置**：某方获得持续 2 回合的防御状态
- **操作**：经过 2 回合
- **预期**：第 1 回合后 lifetime 减为 1，第 2 回合后状态被移除

## 6. API 集成

### TC6.1 — GET /api/games/{id} 返回状态 lifetime
- **前置**：创建游戏并让某方获得状态
- **操作**：调用 `GET /api/games/{id}`
- **预期**：响应中 `players.{1|2}.statuses` 数组每项包含 `{"type": "...", "lifetime": N}`

### TC6.2 — POST /api/games 创建游戏返回正确初始值
- **前置**：无
- **操作**：调用 `POST /api/games`
- **预期**：响应中 P1 和 P2 的 `hp=30`, `energy=2`
